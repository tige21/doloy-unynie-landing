# GSAP затирает CSS transform-центрирование + пин события сжат оптимизацией

**Date:** 2026-07-13 17:05
**Files:** src/lib/scenes/scream.ts, src/styles/scenes/scene0.css
**Severity:** medium

## Problem

(1) Кульминация (рост видео в fullscreen) пролистывалась за один свайп —
событие фильма не проживалось. (2) Контурный «долой уныние» на мобиле
уезжал вправо на полширины и обрезался — повторно, после уже
«исправленного» бага.

## Root Cause

(1) Глобальная оптимизация длины страницы (v3 #30) механически сократила
pin ВСЕХ сцен, включая кульминацию — а у неё метраж и есть содержание:
короткий pin = проскоченное событие. Оптимизация без ранжирования сцен
по драматургической ценности.

(2) Мобильное центрирование `.s0-bg` было сделано через
`transform: translateX(50%)`, при этом GSAP-интро анимирует `y` того же
элемента — по завершении твина GSAP записывает inline
`transform: translate(0,0)` и затирает CSS-центрирование. Предыдущий
фикс проверялся скриншотом ДО завершения интро-анимации, поэтому
регрессия не была замечена.

## Solution

(1) Pin крика 1.1 → 1.9 vh + hold 0.9 → 1.6 юнита — точечно, только
кульминации (+~770px к странице — осознанная цена события).
(2) Центрирование layout-свойствами: `left: 0; right: 0;
text-align: center` — transform полностью принадлежит GSAP. Плюс кегль
19vw (20.5vw давал ширину строки «УНЫНИЕ» ровно во вьюпорт, впритык).

## Prevention

- **Никогда не позиционировать через CSS transform элементы, которые
  анимирует GSAP** — твин перезаписывает transform целиком. Для
  раскладки — left/right/margin/inset или отдельная обёртка.
- Верифицировать визуальные фиксы скриншотом ПОСЛЕ завершения всех
  анимаций элемента (waitForTimeout > длительности интро).
- Глобальные «ужимания» (паузы, pin-длины) не применять к кульминациям
  без отдельного решения — у событийных сцен метраж = содержание.
